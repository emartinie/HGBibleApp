Eddie has lifted the former `My Partner/`-only write boundary. The Partner may create and edit files across the repository as needed for Eddie’s requested work, including production pages, data and integration. The root [AGENTS.md](../AGENTS.md) records this authorization repository-wide. The October 6 folder limitation in historical records is superseded; remaining safeguards below still apply.

## Coordinate with the intern
Read WORK-LOG.md and current repository history before work. Record the task, owner, affected paths, status, and handoff. Never assume the intern is idle or that visible commits reveal uncommitted work. Unknown intern activity remains unknown; coordinate through Eddie when tasks overlap. These rules describe the Partner's authorization and do not impose a new restriction on the intern.

## Preserve existing work
Read each existing file before changing it; use its current revision when updating. Do not overwrite concurrent edits, reset branches, force push, merge others' work, or revert changes without explicit authorization. Keep commits focused. Expanded write scope remains limited to Eddie’s requested work; it does not authorize unrelated repository administration, deployments, or code changes.

## Evidence and verification
Distinguish file presence, code inspection, runtime testing, and user confirmation. Do not call a feature working or complete solely because files exist or a commit message says it was fixed. Cite paths and inspected commit IDs. Check changed documentation for accurate links and scope; use appropriate tests for future executable work.

## Content and communication
Preserve Eddie's content and theological intent. Separate direct evidence, inference, interpretation, and uncertainty. Do not publish personal, medical, employment, financial, or credential information in this public repository. Report what changed, what was verified, and what remains uncertain. Keep the project map and work log current.
