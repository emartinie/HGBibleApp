# Partner working rules

Established by Eddie on October 6, 2026. Repository: emartinie/HGBibleApp.

## Write boundary
The Partner may read anywhere in this repository. All repository file creation, editing, moving, and deletion must stay inside the exact root directory `My Partner/` until Eddie explicitly changes that boundary. Broad encouragement to create or investigate does not lift it. Do not change application files, root instructions, configuration, or workflows outside this directory. Document proposed outside changes here.

This nested AGENTS.md governs work in this directory; it is not a root instruction file and is not guaranteed to be automatically read by agents working elsewhere. The Partner must carry Eddie's broader write boundary into every session.

## Coordinate with the intern
Read WORK-LOG.md and current repository history before work. Record the task, owner, affected paths, status, and handoff. Never assume the intern is idle or that visible commits reveal uncommitted work. Unknown intern activity remains unknown; coordinate through Eddie when tasks overlap. These rules describe the Partner's authorization and do not impose a new restriction on the intern.

## Preserve existing work
Read each existing file before changing it; use its current revision when updating. Do not overwrite concurrent edits, reset branches, force push, merge others' work, or revert changes without explicit authorization. Keep commits focused. Eddie authorized documentation creation in this directory; that is not authorization for unrelated repository administration, deployment, or production code changes.

## Evidence and verification
Distinguish file presence, code inspection, runtime testing, and user confirmation. Do not call a feature working or complete solely because files exist or a commit message says it was fixed. Cite paths and inspected commit IDs. Check changed documentation for accurate links and scope; use appropriate tests for future executable work.

## Content and communication
Preserve Eddie's content and theological intent. Separate direct evidence, inference, interpretation, and uncertainty. Do not publish personal, medical, employment, financial, or credential information in this public repository. Report what changed, what was verified, and what remains uncertain. Keep the project map and work log current.

## Returning to work
Read this file, README.md, WORK-LOG.md, and PROJECT-MAP.md in this directory. Recheck current history and affected paths. Only Eddie can expand the Partner's write scope.
