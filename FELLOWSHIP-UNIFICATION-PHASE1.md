## State and privacy contracts

Canonical URLs/history contain only destination identifiers, reference, translation and week. Identifiers are navigation, never authorization. Private discussion filters/scroll and map viewport stay in bounded memory, cleared on account transitions; they do not survive full reload. Refresh reauthorizes a permalink and fetches the target anew. Reader reference/translation/anchor/offset only are whitelisted in sessionStorage (hg-reading-view-v1); these non-social reading preferences survive refresh in the tab. Storage denial falls back to navigation without exact restoration.

No transcript, body, draft, credential, discovery consent or map coordinate goes into shared history/context storage. Community draft ownership stays with its existing UID-scoped storage. DM drafts retain their existing clear-on-disposal policy; cross-screen DM draft resumption is deferred (N2). A remembered link is a navigation hint from a previously authorized view, not a live membership certificate: destination authorization is checked again. No new background permission listener is introduced. One passive root Auth observer and one before-auth invalidation guard deliberately live for the app visit; repeated mounting must not multiply them. Child screen listeners still tear down.
